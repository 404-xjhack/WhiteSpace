# WriteSpace 留白

面向未来自动化时代的生活探索原型：当机器能做一切，你想亲手做什么？内置人物与活动是明确标注的虚构演示资料；地图使用真实高德底图，个人发布只保存在当前浏览器。

在生产与日常事务高度自动化的设定下，留白帮助人们探索愿意投入的事情、体验人类曾经的手艺与生活，并找到共同参与的伙伴。用户可以发起一次体验或分享自己的经验，查看推荐理由并表达参与意向。技术栈为原生 HTML/CSS/JavaScript、无依赖 Node.js HTTP 服务；无需打包或安装第三方依赖。

内置示例包括自动厨房之外的手工包饺子、为自动化街区绘制散步地图、机器人接管维修后的木工体验、亲子手工劳动、AI 写作时代的手写家书，以及自动影像之外的手机摄影。未来设定用于表达产品立意，当前功能仍是发布、搜索、匹配与参与意向，不包含实际的机器人控制或体验完成记录。

## 当前功能

- 按「发起一次体验」「分享我的经验」区分文案与校验，短标题和短说明也可发布。
- 分享的“希望获得”由 AI 从标题与说明提炼，展示原文依据，允许修改后确认；未提及的诉求显示“未说明”，已有个人分享可重新提炼。
- 分类逐项添加／移除，支持自定义「其他」；列表、详情、搜索和匹配保留全部分类。
- 具体日期或每周时间段；发布时可在真实地图选公共集合点，也可仅填写地点说明而不显示在地图。能力分享可选择时间和地点可协商。
- 参与人数可协商、明确总人数或人数范围；演示资料可保存身份说明与选填年龄，年龄默认不公开。
- 发布时间实时更新，参与意向可取消；刷新后恢复最近匹配，并从每条「我的发布」详情继续查看或重新匹配。
- AI 与本地规则匹配均标记来源；AI 或接口失败时保留可演示的本地匹配。
- 匹配优先比较正文中的需求与实际帮助，自定义标签仅作辅助；可展开全部候选，查看相关但时间冲突的发布。
- 街区地图只使用真实高德底图：进入时以街区尺度申请浏览器定位；拒绝或失败时可搜索地点、按住拖动地图并点选出发点。拖动松开即停；再次点击地图即可更换出发点并重算路线，不保存出发点。
- 地点搜索以纵向列表显示地点与地址；发布者可点地图、搜索或拖动标记确认公共集合点，并写明“见面后先做的一小步”。6 条内置任务每次加载时随机分配在学军紫金港附近的示意点，与真实底图叠加；选定出发点后按高德步行距离比较地图任务，绿色标出最近路线，点开其他任务则以蓝色显示当前任务路线。演示点及其路线仅用于功能参考，不是实际赴约指引。个人发布保留真实选定坐标、路线及编辑／删除能力。

`public/model.js` 提供前后端共用的字段校验、时间格式和规则匹配，`public/map-ui.js` 负责列表／地图视图切换，`public/real-map.js` 负责真实地图、定位、路线和选点，`server.mjs` 负责静态文件、AI 代理、高德 JS 安全密钥代理以及服务端地点／路线请求。

## 启动

需要 Node.js 18 或更新版本，无需安装依赖。

1. 可直接体验本地规则匹配。如需 AI，将 `.env.example` 复制为 `.env`，填入 `AI_API_KEY`；按网关调整 `AI_API_URL` 和 `AI_MODEL`。
2. 在项目目录运行 `npm run dev`。
3. 打开 `http://localhost:4317`。

### 配置真实地图（可选）

在[高德开放平台控制台](https://lbs.amap.com/api/javascript-api-v2/prerequisites)创建应用并添加第一把 Key，服务平台选择 **Web端（JS API）**，取得 Key 和配套的安全密钥。再添加一把 **Web服务 API** 类型的 Key，供地点搜索和步行路线使用；两类 Key 不可互换。将 `.env.example` 复制为 `.env`，填写：

```dotenv
AMAP_WEB_KEY=你的Web端JS_API_Key
AMAP_SECURITY_CODE=对应的安全密钥
AMAP_SERVICE_KEY=你的Web服务API_Key
```

如控制台要求绑定域名，按其提示配置本地 `localhost` 与正式部署域名。修改 `.env` 后重启 `npm run dev`，打开“街区地图”。`AMAP_WEB_KEY` 是会提供给浏览器的 Web 端 Key；安全密钥留在服务端，透过同源 `/_AMapService` 代理用于底图请求。`AMAP_SERVICE_KEY` 仅留在服务端，由本项目的 `/api/map/places`、`/api/map/walking` 访问高德 Web 服务，均不能提交到仓库。浏览器定位需要许可，正式部署应使用 HTTPS；未授权时仍可手动搜索和选点。[高德安全密钥说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)、[Web 服务步行路线文档](https://lbs.amap.com/api/webservice/guide/api/newroute)

仅填写 Web JS Key 和安全密钥时，真实底图与手动点选集合点可用；搜索和步行路线会明确提示还需要 Web 服务 Key。

AI 请求由 `server.mjs` 代理，密钥不会发到浏览器。默认使用 TokenDance（词元跳动）的 `deepseek-v4-flash`，接口为 `https://tokendance.space/gateway/v1/chat/completions`，参考[平台快速入门](https://tokendance.space/docs/quickstart)。AI 匹配和“希望获得”提炼共用这份配置。没有密钥、超时、网关不可用或返回异常时，匹配界面会明确标记为“本地规则匹配”并说明原因。

配置必须写入被 Git 忽略的 `.env`，`.env.example` 只保留空密钥示例。`AI_API_URL` 为完整的 Chat Completions 请求地址。按[平台文档](https://tokendance.space/docs/quickstart)创建 TokenDance 的 API Key，填入 `.env` 的 `AI_API_KEY`；DeepSeek 官网密钥不能用于这个网关。模型 ID 使用平台[公开模型目录](https://tokendance.space/gateway/v1/models)中的 `deepseek-v4-flash`。更换配置后重启服务。

```dotenv
AI_API_URL=https://tokendance.space/gateway/v1/chat/completions
AI_API_KEY=
AI_MODEL=deepseek-v4-flash
PORT=4317
```

“希望获得”提炼使用同一网关，只发送个人分享的类型、标题和详细说明，不发送年龄、身份或地点。只提炼明确写出的诉求，并要求返回可在原文找到的连续片段；没有明确诉求时返回空值。发布前可核对依据、修改或留空，确认后才保存。AI 失败时提示原因，仍可手动填写或留空发布；不将固定文案或本地推测标记为 AI 结果。历史分享可从详情点击“AI 提炼希望获得”，保存后为原发布重新匹配，其他原字段保留。

本地匹配先从标题、说明及对应的需求／能力字段提取中文词语和少量技能别名，判断内容是否相关，再排除明确的技能冲突和时间冲突；按正文证据、供需互补、时间交集、地点及少量标签加分排序。相同标签或不同发布类型本身不足以推荐；加入无关的 `test` 标签不会排除已有的相关人选。分数是规则参考值。默认展示前三项，其余相关候选可展开；时间冲突单独说明，未确定的时间地点仍需协商。AI 可推荐本地词表未覆盖的人选，但也需满足时间和明确技能约束；AI 以外的本地补充候选各自标记来源。

桌面首页的需求列表与匹配栏各自滚动，无需先把需求列表拉到底。两栏使用内嵌的圆角细滚动条和透明轨道，鼠标停留或键盘操作时滑块加深。匹配列表上方显示“展开其他候选（数量）”，展开后可收起；只有确实存在未显示候选时才显示这个按钮和对应的 AI 提示。手机继续使用整页滚动。

## 演示路径

地图演示：配置两类高德 Key 和安全密钥并重启 → “街区地图” → 初始可看学军紫金港附近的随机示例任务，定位到自己后可点“看演示街区”返回 → 在地图上选择演示街区附近的出发点，等待绿色最近步行路线出现 → 点击另一任务，查看蓝色当前任务路线 → “发布附近的事” → 填写标题、说明、分类和时间 → 地点选“在地图选择公共集合点” → 搜索或点击地图，拖动标记微调，确认不是住宅／私人地址 → 填写“见面后先做的一小步” → 发布。个人任务标记和任务卡立即出现。点击地图空白处设定出发点，再点击另一处即可改变出发点并重新比较步行路线；随机示例点与路线不可用于真实赴约。点“编辑”可修改个人任务，点“删除”需二次确认。未配置地图时显示配置提示，列表与匹配仍可使用。

浏览与搜索 → 点击右上角“发布想法” → 选择“发起一次体验”或“分享我的经验”，也可填写未来生活示例 → 添加分类、选择时间地点，按需设置人数和演示资料 → “发布并寻找匹配” → 查看理由与第一步 → 打开对方详情 → “我想参与” → “取消参与意向” → 再参与。

选择“分享我的经验”后，“发布并寻找匹配”先打开“确认希望获得”，自动提炼，核对或修改后点击“确认并发布”；取消会返回原表单并保留填写内容。旧个人分享中的固定“寻找适合的分享对象，具体交流方式见说明”已清空，可重新提炼；演示人物的人工资料保留。

刷新页面仍能看到最近匹配。通过“我的发布”筛选打开任意个人内容，点击“查看上次匹配”或“寻找匹配”，再用匹配面板的“重新匹配”更新结果。匹配面板的“调整活动时间”或个人发布详情中的“调整时间”可修改同一条发布，保存前预览所选日期／星期和时间段，保存后提示实际时间并自动重新匹配；正文、分类、人数、演示资料及原发布时间保留，取消不保存。具体日期同时显示星期，便于理解它与每周安排是否重合。

缓存同时校验算法版本、对应发布及匹配输入，旧版本或内容变化会重新生成，原有发布保留。修改代码后需重启 Node 服务并刷新页面，使前后端使用同一版本。

人数包括发布者，范围为 1–50 人；身份说明选填，默认“社区成员”；年龄选填，接受 1–120 的整数，只有勾选公开才随本次内容展示。资料随成功发布保存，之后发布默认沿用；已有发布保留发布时的资料。

发布时间在 60 秒内显示“刚刚”，一小时内显示分钟数；同一天显示小时数，上一自然日显示“昨天”，更早显示日期（采用浏览器本地时间）。列表与详情每 30 秒更新，回到页面时也更新。旧数据缺少真实时间且只有“刚刚”时显示“发布时间未知”，原有演示相对文案继续兼容。

发布内容、演示资料、参与状态和每条内容的最近匹配暂存在当前浏览器的 localStorage。原型没有真实账户、通知或线下预约；“重置演示”会清空这些本地记录。

## 验证

```sh
npm run check
npm test
npm run test:browser
node tests/map-live.mjs   # 配齐真实高德凭证后再运行
```

前两项检查源码语法与核心规则／HTTP 接口。浏览器检查需要 Node.js 22+ 及已安装的 Chrome、Edge 或 Chromium，可通过 `BROWSER_PATH` 指定浏览器可执行文件。测试使用独立浏览器资料与临时端口，覆盖发布、撤销参与、刷新恢复、请求串用、网络回退及 1280/375/320 像素布局，不触碰个人浏览器资料；截图保存在 Git 忽略的 `.tmp/`。浏览器流程还覆盖模拟定位、纵向地点搜索、地图直接重选出发点、地图发布后的编辑和删除。`tests/map-live.mjs` 用真实凭证和隔离浏览器验收底图、地点搜索及步行 API，不会打印凭证。

本轮 B01–B07、U01–U09 的实现及验证记录见[问题清单与优化说明](docs/problems1.md)末尾。AI 成功、异常和超时使用本地模拟网关测试；当前已使用用户授权的真实 TokenDance 网关及 `deepseek-v4-flash` 验证两组诉求提炼，以及修椅子 + test + 周日的 AI 匹配。更广泛的推荐质量仍需结合实际内容评估。

## 已知限制

匹配候选为内置的六条演示资料，本地记录不会同步至其他浏览器。中文分词与技能别名不能覆盖所有语义，仍可能漏掉没有共同词语的相关内容；推荐需双方确认。周安排目前一次选择一个活动日，时间段需在同一天内。真实地图必须联网且有有效高德凭证，未配置 Web JS Key 与安全密钥时不可选点；未配置 Web 服务 Key 时不可搜索或计算步行路线。地图上的内置任务点每次加载随机分配，仅供演示，不是可赴约的地址；没有真实任务池、账号、通知或跨设备同步。出发点仅在内存中用于当前路线计算，不会被保存；个人发布的公共集合点会保存在本机 localStorage。目前没有真正跨用户的地理匹配，也未接入 SBERT 或 all-MiniLM。

## 后续落地

接入账户与社区认证、持久化数据库、双向同意、站内消息、举报审核、场地与时间确认。真实试点还需审核公共集合点、加强地理信息保护，并对地图代理设置身份鉴别与限流，避免公开服务被滥用。若任务量与文本表达复杂度增加，可在当前本地排序器后增加浏览器端多语言句向量召回，并用真实匹配反馈评估效果；始终保留可解释理由与人工确认。
