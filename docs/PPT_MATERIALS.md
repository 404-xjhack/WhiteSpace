# WriteSpace「留白」PPT 制作资料

整理日期：2026-10-02。适用场景：黑客松项目介绍、产品演示与技术答辩。

本资料依据整理时工作区的 README、产品说明和实际源码整理，包括桌面双栏独立滚动与候选展开入口的当前界面行为。建议制作约 10 页 PPT，面向评委讲解 5–7 分钟。以下问题描述与用户价值属于产品设计判断，项目尚未提供真实用户调研、活跃数据或线下活动成效。

## 一、可直接使用的项目简介

### 一句话定位

WriteSpace「留白」是一个面向未来自动化时代的生活探索原型，帮助人们发现愿意亲手体验的事、了解人类曾经的手艺与生活，并找到共同参与的伙伴。

### 简短项目介绍

在生产与日常事务高度自动化的未来，人们拥有更多自由时间，也需要寻找愿意投入的事情。有人想在自动厨房之外亲手做饭，有人想在机器人接管维修后体验木工，也有人想记录自动化街区里值得记住的日常。WriteSpace「留白」把体验想法和可分享的经验放在同一个工作台中，通过 AI 和本地规则推荐伙伴，说明理由并给出第一步。当前版本已经实现从发布、匹配到参与意向的完整本地演示流程；未来场景、人物与活动均为虚构设定。

### 产品文案

- 产品名称：WriteSpace「留白」。
- 页面主文案：当机器能做一切，你想亲手做什么？
- 核心价值：让自由时间有值得期待的内容，在共同体验中理解过去、探索未来生活。
- 产品阶段：可运行的 Web 演示原型。

### 值得强调的产品亮点

- 以具体体验发起连接：在自动化日常中选择亲手修家具、包饺子、探索街区，表达参与本身的价值。
- 关注参与双方的价值：分享者既能提供帮助，也可以表达自己希望获得的交流与参与。
- 推荐可解释且能开始行动：用户看到匹配理由，还能获得确认时间、地点和分工的建议。
- 保留用户决定权：AI 提炼需要核对确认，参与意向可以撤销。
- 支持稳定的本地演示：外部 AI 服务异常时保留明确标记的规则匹配。

## 二、建议的 10 页 PPT 内容

### 第 1 页：WriteSpace「留白」

**页面内容**

- 当机器能做一切，你想亲手做什么？
- 面向未来自动化时代的生活探索原型。

**讲解要点**：用“机器人已经能修好椅子，但我想亲手试一次，理解过去的木工怎样生活”引入项目。

**配图建议**：产品首页截图，保留品牌、社区内容列表和匹配区域。

### 第 2 页：自动化之后，如何让生活值得期待

**页面内容**

- 当生产与日常事务高度自动化，人们可以自由选择愿意投入的事。
- 体验曾经的劳动与手艺，让过去的生活变成可以亲自理解的过程。
- 让体验想法与分享者相遇，明确时间、地点和开始方式。

**讲解要点**：这是项目采用的未来设定和希望探索的产品问题，不是对当前社会的事实判断。当前没有调研数据，不展示未经验证的比例或市场规模。

**配图建议**：呈现“亲手修椅体验”和“木工体验引导者”的两段实际页面文案，标明虚构演示。

### 第 3 页：目标用户与使用场景

**页面内容**

- 想探索生活的人：尝试亲手修复、手工做饭、写作或街区观察。
- 愿意分享经验的人：传递木工、烹饪、文字与影像记录等手艺。
- 希望理解过去的家庭：让习惯自动化生活的孩子接触人类曾经的日常。

**讲解要点**：社区组织者是后续可能服务的角色，当前没有组织者管理后台。

**配图建议**：选择木工体验引导者、自动化时代的亲子家庭、未来街区探索者三个演示角色。

### 第 4 页：用户使用流程

**页面内容**

1. 浏览未来生活示例，搜索体验、手艺或地点。
2. 发布“发起一次体验”或“分享我的经验”。
3. 填写说明、分类、时间地点与参与人数。
4. 查看推荐理由和建议的第一步。
5. 打开对方详情，表达或取消参与意向。

**讲解要点**：能力分享还会经过“确认希望获得”，用户核对 AI 提炼的诉求后才发布。刷新后可恢复发布、参与状态和最近匹配。

**配图建议**：发布表单、推荐卡片、详情与参与按钮三张截图。

### 第 5 页：当前核心功能

**页面内容**

- 体验内容浏览、关键词搜索、发布类型筛选和“我的发布”。
- 多分类与自定义标签，支持具体日期或每周时间安排。
- 可解释的匹配结果、更多候选与时间冲突说明。
- 调整原发布的活动时间后重新匹配，保留原内容。
- 参与意向可撤销，本地记录刷新后保留。

**讲解要点**：调整活动时间后，原记录的创建时间保持不变。人数支持协商、明确人数和人数范围；年龄选填且默认不公开。能力分享可选择时间、地点可协商。

**配图建议**：匹配卡片与调整活动时间对话框。

### 第 6 页：AI 在项目中的作用

**页面内容**

- AI 匹配：比较需求正文与候选帮助，生成推荐理由和第一步。
- AI 诉求提炼：从分享说明中提取发布者“希望获得”的内容。
- 用户确认：展示原文依据，允许修改、留空或取消。
- 结果约束：校验候选 ID、分数、字段与明确的时间和技能冲突。

**讲解要点**：当前代码默认配置 TokenDance 网关的 `deepseek-v4-flash`。项目调用外部模型，没有训练自有模型。诉求提炼仅发送类型、标题和说明，未写出的诉求保持空值。

**配图建议**：“确认希望获得”界面，展示提炼结果与对应原文。

### 第 7 页：匹配依据与解释

**页面内容**

- 先判断实际需求与帮助是否相关，标签只作辅助。
- 排除明确的时间冲突和技能冲突。
- 结合供需互补、时间交集与地点排序。
- 展示推荐理由、参考分与可执行的第一步。

**讲解要点**：本地规则使用 JavaScript 原生中文分词和少量技能别名。相同分类不能单独证明技能匹配，添加无关标签也不会排除已有的相关人选。AI 可以理解本地词表未覆盖的内容，但仍需通过约束检查。参考分用于辅助排序，不能当作成功率或准确率。

**配图建议**：陈师傅推荐卡片，突出正文相关性、时间条件和行动建议。

### 第 8 页：技术架构与演示稳定性

**页面内容**

- 前端：原生 HTML、CSS、JavaScript。
- 后端：无第三方运行依赖的 Node.js HTTP 服务。
- 共享模型：前后端使用同一份校验与本地匹配规则。
- 存储：浏览器 localStorage 与六条内置演示资料。
- 回退：AI 失败使用本地匹配，接口失败可在已加载资料上由浏览器匹配。

**讲解要点**：运行只需 Node.js 18+，无需安装第三方依赖或打包。AI 密钥保存在服务端 `.env`，浏览器不接收密钥。AI 和本地结果分别标记来源。本次源码检查、29 项规则/API 测试、20 组浏览器流程全部通过。

**配图建议**：用可编辑的架构示意图表现浏览器、Node.js 服务、外部 AI 网关和本地存储。

### 第 9 页：演示案例：机器人时代的木工体验

**页面内容**

- 用户发布：机器人可以修好木椅，但自己想亲手学习修复，了解过去的木工生活。
- 活动条件：每周日 09:00–11:00，社区共享工坊。
- 合适人选：木工体验引导者陈师傅，有基础工具与指导能力。
- 推荐依据：修椅需求与木工能力相关，时间有交集，地点相同。
- 第一行动：沟通修理方式，确认时间、地点与分工。

**讲解要点**：发布后查看理由，打开陈师傅详情并表达参与意向。可以额外展示改到周六后的冲突说明，再改回周日重新匹配。若 AI 本次未推荐陈师傅，可展开本地候选；本地规则路径已验证。

**配图建议**：完整修椅推荐结果，加一张时间冲突或参与详情截图。

### 第 10 页：当前阶段与后续落地

**页面内容**

- 已完成：发布、匹配解释、诉求提炼、意向操作和本地恢复。
- 当前范围：六条内置候选，演示资料仅保存在当前浏览器。
- 下一阶段：账户与社区认证、持久化数据库、双向同意和消息。
- 上线前补充：举报审核、活动确认与线下安全机制。

**讲解要点**：当前参与操作不会通知真实用户，也不代表预约成功。后续先通过小范围社区试用验证需求和推荐效果，再决定扩展方向。

**配图建议**：用简洁的“当前原型 / 社区试用 / 正式服务”阶段图，后两阶段标记为规划。

## 四、现场演示脚本

### 准备

在项目目录运行 `npm run dev`，打开 `http://localhost:4317`。无需 AI 密钥即可演示本地规则匹配；需要真实 AI 时，使用被 Git 忽略的 `.env` 配置 `AI_API_KEY`、`AI_API_URL` 与 `AI_MODEL`，配置后重启服务。保留当前浏览器演示记录，只有在确定可以清空时才使用“重置演示”。

### 主路径，约 90 秒

1. 介绍首页的未来设定与生活体验，说明人物和活动是虚构演示资料。
2. 点击右上角“发布想法”，展开“不知道怎么写？填写一个未来生活示例”。
3. 点击“亲手修复旧椅子”，核对机器人时代的木工体验正文、每周日 09:00–11:00、社区共享工坊。
4. 点击“发布并寻找匹配”，展示 AI 或本地来源标记。
5. 查看陈师傅的推荐理由和第一步；必要时展开其他候选。
6. 点击“了解这次体验”，依次演示“我想参与”“取消参与意向”“我想参与”。
7. 刷新页面，展示记录与最近匹配恢复。

### AI 诉求提炼，约 45 秒

1. 新建发布，选择“分享我的经验”，也可填写“记录自动化街区”示例。
2. 标题：“分享手机摄影，记录自动化街区的日常”。
3. 说明：“自动影像系统已经能记录整座城市，我仍想和大家亲自选择值得拍下的瞬间。可以教手机摄影和简单修图，也希望听你分享照片背后的社区故事；具体交流方式可先商量。”
4. 提交后进入“确认希望获得”，展示提炼与原文依据。
5. 修改或确认结果，发布后从详情查看“希望获得”。
6. AI 不可用时展示明确提示，手动填写或留空仍可发布。

### 时间约束，约 30 秒

从原发布的匹配面板点击“调整活动时间”，改为每周六 09:00–11:00并保存。展示陈师傅每周日的时间冲突，再改回每周日重新匹配。这里证明系统考虑可执行条件，不代表线下活动已经预约。

## 五、技术答辩资料

### 当前架构

| 部分 | 实现 | 作用 |
| --- | --- | --- |
| 页面结构 | `public/index.html` | 列表、表单、详情、匹配与确认对话框 |
| 页面样式 | `public/styles.css` | 纸白与社区绿，桌面双栏，移动端单栏 |
| 前端交互 | `public/app.js` | 发布、搜索、意向、缓存、取消请求与网络回退 |
| 共享规则 | `public/model.js` | 字段校验、时间兼容、中文分词、匹配评分与解释 |
| 后端服务 | `server.mjs` | 静态文件服务、AI 请求代理、校验和回退 |
| 演示候选 | `public/data.json` | 六条内置社区人物与活动资料 |
| 本地记录 | localStorage | 个人发布、演示资料、意向与每条发布的匹配结果 |

后端接口：`GET /api/status` 查询是否配置 AI；`POST /api/match` 请求匹配；`POST /api/extract-need` 提炼分享者希望获得的内容。

### 为什么采用简单技术栈

原生 Web 与 Node.js 能完成当前核心流程，减少依赖安装、构建和部署环节，符合 48 小时黑客松优先保证可运行演示的要求。当前没有引入数据库、向量检索服务或前端框架。

### AI 不可用怎么办

匹配服务在未配置密钥、超时、上游错误或异常返回时使用本地规则，并展示回退原因。浏览器请求失败时，可使用已载入的候选资料计算本地结果。诉求提炼失败后允许人工填写或留空。该机制保障已启动且资料可用时的演示，不等同于完整离线 Web 应用。

### 如何限制 AI 编造

匹配候选来自已知资料，程序过滤未知和重复 ID，校验分数、解释字段及明确约束。诉求提炼要求返回可在原文中逐字找到的连续依据，用户再核对确认。原文依据校验不能保证语义绝对正确，仍需人工确认。

### 如何避免旧结果覆盖新操作

前端取消旧请求并检查请求版本与当前发布。匹配缓存校验算法版本、发布 ID 与输入指纹。诉求提炼在用户输入、关闭或取消后使旧请求失效，晚返回的内容不会覆盖手动文本。

### 后续应验证哪些价值

建议在获得同意的社区试用中观察用户能否找到愿意投入的体验、双方是否愿意进一步联系、参与后的收获，以及推荐不适配的原因。这些只是后续评估方向，目前没有相关实测指标。

### PPT 中需要准确表述的边界

- 自动化时代是虚构的产品场景，所有人物、活动和互动为演示数据，无真实用户规模或成功活动数据。
- 服务端推荐候选固定为六条内置资料，尚未接入多用户社区数据库。
- localStorage 保存的是当前浏览器的数据，支持刷新恢复，不支持跨设备同步。
- “我想参与”只记录本地意向，没有真实通知、聊天、双向同意或预约。
- 页面中的社区与地点为预设内容，没有地图、定位或地理距离计算。
- 当前用户表单每周安排一次选择一个活动日，时间段需在同一天内。
- 本地中文分词和技能别名覆盖有限，可能漏掉相关内容。
- 推荐分数是参考值，不能作为准确率、成功率或实际匹配效果的证据。
- 项目没有自有训练模型，外部模型名称是当前代码默认配置。

## 八、交给 PPT 制作工具的提示词

> 请根据本资料制作一份用于黑客松答辩的中文 PPT，项目名称为 WriteSpace「留白」，共 10 页，讲解约 5–7 分钟。主文案为“当机器能做一切，你想亲手做什么？”，明确采用未来生产与日常事务高度自动化的虚构设定，核心价值是探索生活、充实自由时间、体验人类曾经的手艺与日常。按“项目定位、自动化之后的生活探索、目标用户、使用流程、当前功能、AI 作用、匹配逻辑、技术架构与稳定性、机器人时代的木工体验演示、当前阶段与规划”的顺序组织内容。每页使用简短标题和少量正文，将补充技术解释放在演讲备注。采用纸白、社区绿和深墨色的品牌风格，优先使用产品截图与可编辑流程、架构示意。准确区分已实现功能和未来规划，标明未来场景、人物与活动为虚构演示。不得编造用户数、市场规模、效果提升、模型准确率或线下成功案例。当前版本测试结果为 29 项规则/API 测试与 20 组浏览器流程通过。参考分只用于推荐排序。真实账号、消息、地图、预约、云数据库和跨设备同步属于后续规划。
