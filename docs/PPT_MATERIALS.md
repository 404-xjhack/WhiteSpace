# WhiteSpace「留白」PPT 制作资料

更新日期：2026-10-03。适用场景：黑客松“重构赛道”项目介绍、产品演示与技术答辩。

建议制作约 10 页 PPT，面向评委讲解 5–7 分钟。资料以当前源码与 README 为依据；问题描述和社区价值属于产品设计判断，没有真实用户调研、活跃数据或线下协作成效。人物、发布和地图任务均为虚构演示资料。

## 一、可直接使用的项目简介

### 一句话定位

WhiteSpace「留白」是一个附近协作原型，从“我想做什么”出发，帮助社区里的兴趣、技能与需求互相发现，让找人一起做事更容易开始。

### 简短项目介绍

想修好一把旧椅子、学摄影，或找人一起认识街区，往往要先在群聊和社交平台发消息，等待回应，再一个个沟通是否合适。身边有需要，也有时间、能力和兴趣，缺少的是让它们互相发现的方式。留白把想做的事与可以分享的能力放在同一个工作台中，通过 AI 或本地规则推荐伙伴，解释理由并给出第一步。当前已实现发布、匹配、参与意向和本地恢复；真实附近协作是产品方向，候选仍是六条虚构资料，意向不会发送给真实用户。

### 产品文案

- 主标题：想做一件事，找到一起做的人。
- 副标题：说出你想做什么，AI 帮你寻找合适的伙伴，让附近的活动、互助和协作更容易开始。
- 核心立意：我们重构的，是“找人一起做一件事”这件再普通不过的事情。
- 社区价值：让身边已有的能力派上用场。
- 页脚：让想做的事，遇见一起做的人。
- 产品阶段：可运行的 Web 演示原型。

### 评委应能回答的三个问题

| 问题 | 回答 |
| --- | --- |
| 重构了什么？ | 找人一起做一件事的方式。 |
| 今天有什么问题？ | 兴趣、技能与需求就在身边，却很难互相发现。 |
| 让什么变简单？ | 从说出想做的事，到获得合适的伙伴建议和开始行动的第一步。 |

## 二、建议的 10 页 PPT 内容

### 第 1 页：想做一件事，找到一起做的人

介绍“留白 / WhiteSpace”和附近协作定位。以“椅子坏了，自己不会修，附近却有人会木工”引入。展示首页首屏，注明“原型 · 示例人物”。

### 第 2 页：想法有了，一起做的人在哪里？

用简短流程呈现当前麻烦：有想法 → 在群聊或帖子发消息 → 等待回应 → 反复确认能力、时间和地点 → 尝试一起开始。强调需要与愿意帮忙的人难以互相发现。不要编造放弃比例、市场规模或效率提升数据。

### 第 3 页：从一件具体的事开始

展示当前可操作流程：

1. 描述想做的事或可以分享的能力，补充分类、时间和地点。
2. 查看伙伴建议、推荐理由、冲突或待确认条件。
3. 获得第一步建议，打开详情，表达或取消参与意向。

说明参与只记录在本机；真实联系和双方同意仍待落地。用发布表单与推荐卡片说明，不把流程画成已经自动联系、预约或组队。

### 第 4 页：今天就可能发生的连接

选取三个已有场景：旧椅子与木工指导、想学手机摄影与愿意教的学生、想带孩子包饺子与愿意分享手艺的王阿姨。还可展示街区散步、写作交流和亲子动手。关注互补与共同参与，不展示职业履历排行榜。

### 第 5 页：当前产品能做什么

- 浏览、关键词搜索、类型筛选、个人发布的编辑与删除。
- 多分类、时间安排、地点和人数条件。
- 匹配理由、第一步建议、其他候选与时间冲突提示。
- 按参与条件从他人发布中推荐可以了解的事。
- 真实高德地图、公共集合点、选点和步行路线。
- 饺子工坊六步体验、学习记录与文字时间胶囊。

地图需要有效凭证和网络；工坊及胶囊展示具体尝试与记录，不证明已发生线下协作。

### 第 6 页：AI 帮助理解这件事需要谁

比较正文需求与实际帮助，分类和标签只作辅助。考虑时间条件和明确技能约束，说明为什么合适、各自能带来什么，并给出第一步。能力分享的“希望获得”从原文提炼，展示依据，由用户修改、留空或确认。

地点文本可以提供同地参考；当前不按真实用户的地理距离匹配。分数只用于排序，不能称为成功率或准确率。AI 无法使用时，匹配与发布推荐有明确标记的本地回退。

### 第 7 页：演示：一把旧椅子如何找到帮手

用户发布“想修好一把旧椅子，找会木工的人一起”，选择每周日 09:00–11:00。查看陈师傅的工具、木工指导、时间交集及第一步；地点仍需双方确认。打开详情，表达、取消并再次表达参与意向，刷新后查看恢复。

可以将时间改为周六，展示陈师傅的时间冲突，再改回周日。展示的是减少发现和确认的阻力，不把本地意向称为已经完成维修。

### 第 8 页：让身边已有的能力派上用场

解释希望产生的社区价值：技能分享让想学与愿意教的人相遇，旧物修复有助于继续使用已有物品，同行活动让新居民认识街坊，跨代交流让经验有机会传递。发布中可以说明愿意带来的时间、工具、设备或可用空间。

这些是用途与目标，当前没有专门的资源调度功能、真实试点数据或已验证的资源节省效果。

### 第 9 页：简单架构，清楚边界

原生 HTML/CSS/JavaScript + 无第三方运行依赖的 Node.js HTTP 服务。共享校验与本地匹配规则，个人数据保存在 localStorage，候选来自六条内置资料。AI 密钥保留在服务端；AI、接口和地图故障有相应提示或回退。

说明已有真实地图及地点／路线能力，同时明确没有真实账户、邻居资料库、通知、聊天、双向同意、预约或跨设备同步。地图演示点随机分配，不能作为真实赴约地址。测试结果只引用实际记录，不使用过期计数。

### 第 10 页：让人与人的协作更容易

最后才引入长期愿景：当更多重复事务被自动化，人们或许能把更多时间用于创造、兴趣和帮助他人。我们希望人与人的协作能像使用互联网服务一样容易开始。

收尾：“AI 应该让人与人的协作更容易。”

下一阶段先进行获得同意的小范围社区试用，逐步接入账户与社区认证、持久化、真实附近匹配、双向同意和消息；上线前完善活动确认、举报审核与线下安全机制。这些全部标记为规划。

## 四、现场演示脚本

### 准备

运行 npm run dev，打开 http://localhost:4317。没有 AI 密钥也能演示本地匹配。需要真实 AI 时使用被 Git 忽略的 .env，填写 AI_API_KEY、AI_API_URL、AI_MODEL 后重启。地图需要两类高德 Key 与安全密钥，详见 README。仅在确定可清空演示记录时使用“重置演示”。

### 主路径，约 90 秒

1. 用首页标题说明产品，指出示例人物与本机意向。
2. 点击“发布想法”，展开“不知道怎么写？试试一个社区示例”。
3. 点击“找人一起修旧椅子”，核对正文、每周日 09:00–11:00 和待确认的公共集合点。
4. 点击“发布并找伙伴”，展示 AI 或本地来源。
5. 查看陈师傅的推荐理由与第一步，必要时展开其他候选。
6. 点击“了解这件事”，演示“我想参与”“取消参与意向”和再次参与。
7. 刷新页面，查看个人发布、参与状态与匹配恢复。

### AI 诉求提炼，约 45 秒

选择“我能分享或帮忙”，或填写“分享手机摄影”示例。标题为“可以教手机摄影，也想听听街区故事”，正文表达能教摄影、简单修图，以及希望听社区故事。提交后核对“确认希望获得”的提炼和原文依据，可修改或留空，再确认发布。AI 不可用时展示明确提示，仍可手动填写或留空。

### 可选演示

- 时间约束：改为周六，展示陈师傅周日的冲突，再改回周日。
- 工坊：王阿姨详情 → “进入饺子工坊” → 六步操作 → 返回详情。
- 时间胶囊：完成六步 → 回顾页保存自己的文字作品和两条感受 → 重新打开或导出 .txt。
- 地图：查看示例任务、选出发点、查看步行路线；强调随机示例点不可用于真实赴约。

## 五、技术答辩资料

| 部分 | 实现与作用 |
| --- | --- |
| 首页与样式 | public/index.html、public/styles.css：社区工作台、产品说明、双栏及手机布局 |
| 前端交互 | public/app.js：发布、意向、缓存、请求取消与网络回退 |
| 共享规则 | public/model.js：校验、时间兼容、中文分词与匹配解释 |
| 他人发布推荐 | public/experience-planner.js：筛选已有发布、确认未知条件和缓存 |
| 地图 | public/map-ui.js、public/real-map.js：定位、公共集合点、地点搜索和步行路线 |
| 后端 | server.mjs：静态文件、AI 代理、地图配置及高德服务代理 |
| 演示候选 | public/data.json：六条虚构社区资料 |
| 工坊与胶囊 | public/experiences/dumpling/、public/time-capsules.js：六步体验、本地记录与文字导出 |

接口包括 GET /api/status、POST /api/match、POST /api/extract-need、POST /api/recommend-experiences、GET /api/map-config、GET /api/map/places 和 GET /api/map/walking。当前代码默认使用 TokenDance 网关的 deepseek-v4-flash，没有训练自有模型。

运行仅需 Node.js 18+；浏览器测试需要 Node.js 22+ 及已安装的 Chromium 浏览器。没有框架迁移、数据库或向量服务。未配置 AI、超时、上游错误或返回异常时使用本地匹配；诉求提炼失败不编造结果，允许人工填写。地图故障不伪造底图或真实附近任务。

AI 输出只能引用已知候选；程序过滤无效 ID、重复结果和明确冲突。诉求提炼要求原文依据，仍须用户确认。匹配缓存校验版本、发布 ID 和输入；修改或取消后旧请求不能覆盖当前操作。示例改文案后缓存版本为 content-v3，个人发布和参与记录保留。

## 六、验证与事实范围

本轮语法检查、64 项规则／接口测试、30 组主站浏览器流程、8 组工坊流程和 6 组胶囊流程全部通过。覆盖发布、参与撤销、刷新恢复、旧缓存更新与个人数据保留、时间冲突、AI 与网络回退、地图、工坊和胶囊，以及 1280/375/320 像素布局和叙事区跳转。AI 成功与异常由本地模拟网关验证；本轮不额外调用真实 AI 或地图服务。执行环境与截图记录见 README。

答辩时始终区分：

- 产品定位是附近协作，当前候选是固定示例资料，没有真实邻居的地理匹配。
- 有真实高德地图、定位及路线功能，演示任务地址仍为随机示意点。
- 参与意向仅在本机保存，不是通知、预约或已建立的关系。
- 用户规模、线下活动结果、资源节省与推荐效果均未验证。
- 当前时间字段需在同一天内，每周安排一次选择一个活动日。
- 本地词表覆盖有限，可能漏掉相关内容；未知时间、材料或余位仍需确认。

## 七、交给 PPT 制作工具的提示词

> 请根据本资料制作 10 页中文黑客松答辩 PPT，项目名称 WhiteSpace「留白」，讲解约 5–7 分钟。主文案“想做一件事，找到一起做的人。”，立意为重构“找人一起做一件事”的方式。按重构对象、今天的发现困难、意图与伙伴建议、社区使用场景、已实现功能、AI 作用、修椅演示、社区价值、架构与真实能力边界、末尾长期愿景组织内容。自动化只在最后作为可能带来更多创造和互助时间的背景，不用失业或人类失去价值引入。保留纸白、社区绿和深墨色风格，使用实际产品截图与可编辑流程图，截图注明示例资料。准确区分现有真实地图功能与尚未实现的真实邻居匹配、消息和实际组队。不得编造用户数、市场规模、效率、模型准确率、资源节省或线下成功案例。测试结果仅引用 README 本轮验证记录。
